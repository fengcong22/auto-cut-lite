# 原生音频尾差与独立完整性检查

适用于 Auto-Cut Lite `1.6.12+codex.20260917113552`。

原视频时间轴比原生音轨长不超过 50 ms 时，先证明音轨完整，再仅为 ASR 诊断
副本补尾部零采样。16 kHz 下上限为 800 点，超过上限拒绝处理。原音、替换音源
和交付素材不因此补白或拉伸；视频总时长及后续片段的位置保持不变。

## 独立证据

- 通过 FFprobe 检查解码帧的原生采样数与时间戳连续性；前置静音照常计数。
- 音轨存在非零起点、内部间断或时间漂移时拒绝处理，不将第一处有声波形视为起点。
- 从权威原文件重新解码 16 kHz PCM，与尚未补尾的识别 WAV 比较采样数及 PCM 哈希。
  抽取过程中少一采样点、同长度内容被改写或文件截断均失败。
- 原文件、诊断文件及验证收据以 SHA-256 绑定。时间戳量化与重采样的舍入误差单独
  记录，不使用 50 ms 容差放过处理过程中的损失。
- 替换音频必须保留原轨真实覆盖范围，并继续通过原有同步相关性、偏移和漂移检查。
  修音会改变波形，覆盖与相关性检查不能等同于逐字语义完整性证明；审核作业继续
  保留完整候选反向 ASR 与必留词验收。

A1/A2 按实际音频覆盖范围构造并校验互补窗口，不引用诊断补零区。
runner 升级到 v12，旧阶段回执必须重新校验；输入参数和结果结构保持兼容。

## 验证范围

回归覆盖 148、500、800 点原生尾差，801 点越界，抽取损失 1、148、500 点，
前置静音、非零起点、内部时间戳间断、内容篡改，以及单素材与多素材可编辑草稿。

现场失败素材的原轨在 44.1 kHz 下包含 34,584,576 点；转换为 16 kHz 后为
12,547,692 点，相对 784.24 秒视频少 148 点（9.25 ms）。独立解码 PCM 哈希
完全相同，补尾后原 PCM 前缀不变、仅追加 148 个零采样，原文件哈希不变。
此验证没有调用付费 ASR，也没有重跑业务任务。

全库测试环境另有既存缺件：音频迁移清单引用的 Git 历史对象不可达，且缺少历史
FFmpeg 资产构建回执和资产清单。本次不伪造这些输入；Lite 插件发布仍必须通过
自身的完整包清单、解包哈希及目标安装完整性校验。
