# ASR 诊断音频采样精度修复

插件版本：`1.6.11+codex.20260916152428`；内嵌核心仍为 `1.7.0`。
本次只交付新版包，不部署、不修改 Taskboard、不重跑生产任务。

## 已核实的原因

现场失败记录的模式为 `video_original`。视频时长 `627.589002 s`，
识别 WAV 为 16 kHz 单声道 PCM16，共 `10,041,423` 帧，时长
`627.5889375 s`。代码按视频时间四舍五入需要 `10,041,424` 帧，
因少一帧报 `source_pair_asr_integrity`，尚未调用本次源 ASR。
这与此前卸载造成的 ASR 配置缺失是两个问题。

在源码侧复制现场失败 WAV 后，验证补一个诊断零样本即可通过；原任务文件哈希未变。
该检查没有访问 ASR 服务，也不证明任务其余阶段已经通过。

## 严格边界

- 原始抽取缓存、原视频、原音、修音文件及草稿交付材料保持不变。
- 对传给 ASR 的工作副本，目标为 `round(video_duration * 16000)` 帧。
  仅允许相对该目标少一帧，补一个零 PCM 样本；少两帧或更多、空文件均阻断。
- 一帧为 `62.5 µs`；视频容器时间通常不在采样网格上，因此比较的是整数帧数，
  不是固定 `62.5 µs` 的时长差阈值。现场差为 `64.5 µs`，补齐后仍有约 `2 µs`
  的不可表示尾部量化误差。回执分别记录帧数与真实时长差。
- 校验固定格式及完整 PCM 负载，包含将被裁掉的尾部。头部虚报长度、截断一个
  样本或错误格式都不能被容差掩盖；失败继续使用完整性错误码，不降级为标签成功。
- 多视频拼接另按累计视频时长的最近采样点确定边界，每对相对本地四舍五入的
  WAV 最多再增减一个诊断尾部样本。此操作单独记录为拼接网格量化，不计入
  本地缺音容差，也不扩大其一帧上限。每个累计边界误差不超过半个样本，
  避免误差随素材数量累积。
- ASR 词时间仍加原视频的权威 offset；A1/A2、标签、画面及总时间轴不移动。
  工作音频覆盖与同步检查、保存验收保持有效，不能用诊断补齐延长真实工作素材。

单视频与 source_pairs 使用相同的诊断校验。内部 source ASR index 和配对回执
增加原始/输出帧数、短缺秒数、补齐/裁剪帧数与累计边界映射。源 ASR 缓存绑定
调整后副本哈希，反向 ASR 缓存绑定候选字节。Runner 更新为
`auto-cut-lite-review-document-run-v11-sample-precision`，使旧阶段回执重新验收。
调用参数、`result.json` v1、package receipt v2 和 ZIP 约定保持兼容。

## 验证与限制

先写失败回归再修复，首轮 11 failed / 1 passed。覆盖现场精确数值、旧单视频、
配对顺序、20 段累计拼接正负舍入、真缺音、空 WAV、负载截断、格式错误、
候选时长、源/缓存字节保留和 v10 阶段失效。

最终针对性验证共 210 项通过（去重计数）：采样边界 20 项、相关流水线/隔离/
工作音源 103 项、发布/反向候选 81 项、新增真实媒体 4 项、真实草稿及 ZIP 2 项。
真实媒体使用 30000/1001 fps H.264 + ALAC MP4，视频 3.003 s，
分别构造抽取后缺 1、2、160 个 16 kHz 样本；旧函数两项失败，修复后全部通过。
草稿 ZIP 测试使用既有精确时长媒体夹具，不能称为现场失败任务完整重跑。
源码独立审查未发现阻断项，Ruff 与 Git 空白检查通过。
本次没有重复全库测试；此前全库三个历史/构建输入缺失项仍见工作音源修复记录。
readiness 每项测试使用临时路径，正式 readiness 测试前后按 SHA-256 核对。
测试与打包回执保存在忽略目录 `tmp/sample-precision-fix/` 和 `tmp/releases/`。

一个样本的差异只能按明示精度政策容许，不能从帧数证明差异确由取整造成，
也不能据此证明语音或口型同步。现有工作音源同步门槛不放宽。
离线真实媒体验证不等于真实付费 ASR 成功或剪映 UI 试听；现场任务没有重新执行。
